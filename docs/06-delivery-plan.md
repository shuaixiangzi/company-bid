# 实施与验收计划

实施顺序围绕“能产出有用 Word”和“每一步都能诊断恢复”。2026-11-11 用户明确调整下一阶段：先把新产品需要的旧系统核心能力完成独立改造、接成完整主链，再用整份真实招标文件逐节点查验；不继续只打磨人工准备的局部 Word，也不先建设平台。M1 历史验证见 [M1 原型](07-m1-prototype.md)，当前整链实施见 [整链改造与诊断验证](09-full-chain-migration.md)。

## M1 有真实内容的文档原型

从已授权使用的代表样本选取至少一组固定表格、一项公司证明附件、一个实质技术章节和一个缺项。建立输入/output schema、最小节点运行包装、日志/trace 和受控产物目录；原型可以先从人工整理的准确输入开始，明确不冒充全自动解析结果。

验证：模型是否按项目要求写出可用方法；事实能否指回材料；表格、图片和缺项是否真正进入可编辑 DOCX；Word/WPS 中能否打开、修改和更新目录。每次调用保存版本、输入输出与校验记录。

退出条件：源文/材料逐项核对表、实际 Word、待补清单、一次单节点失败后重跑证据齐全。如果关键技术章节仍只是通用空话，或附件只剩 ID，则先修该节点，不以搭好网页作为进展替代。

2026-11-11 用户指定人工标书作为内容和样式质量基准，并要求优先检查旧设计。已完成[逐环节复用复核](08-legacy-design-reuse.md)，并在 M1 独立实现精简 WritingTask、适用参考改编、表格完整性校验和冻结样式；真实选定范围扩展为 12 个技术单元与 3 张拟用记录表。逐项来源和最终 Word 验证见 [M1 记录](07-m1-prototype.md)，本轮新增模型调用为 0；不把加小标题或增加页数当作质量达标，也不提前进入 M2 平台搭建。

## M1.5 核心能力整体改造与整链验证（当前）

按 [旧设计复核](08-legacy-design-reuse.md) 独立实现本产品所需的 N0～N6：原件冻结、PDF/DOCX 分页或对象读取与按需 OCR 接口、分窗要求/响应格式提取、原格式编排、公司事实与证明匹配、技术写作、检查和 Word 发布。保留原格式段落、表格坐标/合并及来源。模型只产候选，业务代码校验后填入事实和装配文件。不迁移多公司、在线改稿或旧 ORM/迁移链等本产品不需要的模块。

使用现有同一个本地执行器接通所有节点；每个迁入能力同时交付成功/失败输入输出、版本/hash、实际调用与重试、trace、覆盖分母、单元 checkpoint 和明确采集状态。关键格式无法读取或定位时停止；已知要求缺公司资料、报价或签章时保留待补。增加只读诊断索引，检查证据是否存在且一致，不能把日志文件存在等同于可排查。

迁移时先做必要的局部负例和合成整链测试，以避免把基本程序错误带进付费验证。主链接通后，用整份真实招标文件执行并逐环节审查；收费调用前检查输入/窗口/输出合同及费用上限，失败只补未完成单元，代码或配置变化按既定语义创建子 run。人工标书继续作为内容与样式质量参照。

退出条件：完整真实输入不依赖人工整理的要求、目录或正文，可生成经源文核对和逐页视觉检查的 Word；原表、技术正文、实际证明、缺项有明确映射；真实失败定位和局部续跑证据可查。没有实际接通的 OCR、附件格式或资料导入能力逐项列明，不以接口存在冒充完成。CLI 阶段不宣称 PostgreSQL Worker、多人权限或并发已经验收。

## M2 可恢复的最小运行底座

建立独立项目代码、数据库迁移、文件接口、超管/成员账户、项目所有者、run/job/attempt/节点产物和统一执行器。成员只读写本人项目，超管可全量查看；公共公司资料与私有项目补充资料分开授权。先用确定性测试节点覆盖完整提交、失败和恢复，再接入 M1 能力。不实现公司主体核对或多公司隔离。

实现真实 PostgreSQL 领取、租约/token、取消、checkpoint、单步暂停、resume 和 rerun_from。输入与执行清单冻结；最终结果与 job 完成同事务；不建立 current pointer。

观测在本阶段完整接入：JSON 日志、OTel、节点输入输出、实际外部调用尝试、持久 trace 和采集状态。Jaeger 等查看端不可用时仍能通过本地记录和数据库定位节点。

退出条件：进程崩溃前后、同 run 并发继续、过期 attempt、取消与完成竞争、文件/数据库失败、trace 导出中断均有确定性验证；已成功输入/产物不会被重跑覆盖。开发者已能通过 CLI/API 单步而无需重跑整份文件。

## M3 跑通完整自动制作

将 M1.5 已验证的完整 N0～N6 接入公司资料入库、真实上传、独立 Worker 和授权下载；补足原型明确列出的 OCR/文件格式/材料资格过滤边界。沿用同一业务节点，不为网页另写生成链路。

先固定一个模型和一个 OCR 适配器，用输出 schema 隔离实现；不先做多 Provider 竞速或智能选模。配置每 run 调用/页数/时间/费用上限与最大重试次数，根据 M1 测量锁定。超预算有明确停止或待处理原因，不能靠不断全文件重跑碰成功。

首批测试矩阵至少覆盖：文本 PDF、扫描/混合 PDF、含表格或嵌图的 DOCX；资料齐备和资料缺失；固定格式与自由技术章节。准确标注源文关键要求，不能把旧系统输出设成金标。

退出条件：无需在线确认目录即可得到有实质正文的 Word；缺项清楚可补；关键读取遗漏不会假报成功。每种输入格式的支持边界与实际样本结果对应。

## M4 最小使用界面与调试工作台

实现公司资料、项目/上传、进度/结果和调试详情。先做完成任务所需操作，不做目录或 Word 编辑器。允许上传时一次设置项目补充资料，其后自动推进。

调试详情必须能查看节点尝试、真实输入输出、调用 trace、失败原因、复用来源和新旧差异；提供继续、单步和从指定节点重跑。配置覆盖只允许白名单字段，不能从网页执行任意代码或读取任意文件。

退出条件：浏览器刷新/关闭不改变任务状态；重复操作幂等；成员只查看、下载和操作本人标书，超管可查看全部及敏感诊断；成员不能通过列表、状态接口或直接链接读取他人资料；两个重跑版本可以清楚对比。

## M5 三人使用与部署恢复

用 3 个成员账号各自提交独立代表项目，并用超管账号验证全量查看，记录每个任务实际推进区间，验证配置的 3 活跃槽与共享 Provider/OCR/渲染限额。暂停、恢复、取消和新调试分支同时发生时仍可定位且不串资料；交换项目/run/文件标识验证成员之间不可读写。

完整部署验证应覆盖网页/API、Worker、数据库、文件存储、模型/OCR 和 trace 查看端。测量硬件、样本页数、队列等待、节点耗时、峰值内存/CPU、限流、调用量和单份成本；据此决定槽位，而不是提前承诺生成时间。

执行一次数据库与文件一致备份，在新库/新目录恢复。验证历史 Word 下载 hash、必要 checkpoint、资料版本和失败任务续跑。记录数据保留、更新部署、回退与恢复操作。

退出条件：三用户功能与资源边界通过，备份真的能恢复，原文/Word 人工核对完成。保留真实未跑项，不将合成测试、skip 或单用户试跑包装成容量和业务质量通过。

## 验收矩阵

| 领域 | 必测场景 | 成功证据 |
|---|---|---|
| 上传/读取 | 伪装类型、路径穿越、损坏文件、扫描页、DOCX 嵌图/表格 | 原件 hash、覆盖账本、确切失败对象，无静默漏读 |
| 要求提取 | 金额/否定/强制条款、跨窗条件、截断/失败窗口 | 对标注样本的逐项映射；关键要求遗漏为零，结论仅限样本 |
| 资料与写作 | 过期/错人员或证书类别/派生资料、缺报价、无历史范文技术方案 | 事实无虚构；方案针对要求；缺项不冒充满足；不设公司主体核验门 |
| 文档效果 | 实际表格和证明页、章节层级、跨页、目录、图片 | Word/WPS 视觉检查和可编辑性；缺项编号双向对应 |
| 自动流程 | 从上传到下载，全程无需目录确认 | 正式接口与 Worker 链路、已存结果 hash |
| 日志与 trace | 成功、失败、重试、复用、Provider 超时/截断 | 每个实际 attempt 可定位；用量未知如实记录；捕获状态完整 |
| 单步与续跑 | 单节点暂停/继续、失败窗口重试、返回上一步、修改 prompt | 已成功前缀复用、下游失效、新旧产物不覆盖 |
| 故障恢复 | 崩溃、租约过期、迟到、取消竞争、提交结果不明 | token/幂等守卫有效，仅发布一次，无盲删文件 |
| 权限与敏感数据 | 成员跨项目列表/状态/下载/命令、超管全量读取、诊断访问、源文/密钥 canary | 成员只操作本人标书，超管可查看全部；公共资料不泄漏私有项目；普通日志/trace 无敏感正文或凭据 |
| 三人并行 | 三账号、多项目、调试与正常任务混合 | 实际推进区间和资源记录，无超限/饥饿/状态混淆 |
| 备份恢复 | 新目标恢复数据库、原件、结果与 checkpoint | hash 核验、历史下载和恢复执行实测 |

“覆盖”拆分为已实质响应、待人工补充和无需正文三类，待补不能计作实质响应。模型复核评分只作辅助，不能替代来源和人工核对。

## 开发与验证纪律

- 每次只跑受影响的节点和负例；修复失败点后先局部复验，再跑一次相应纵向链路。
- 每个里程碑冻结代码版本、输入 manifest、配置和实际结果，保留新旧尝试差异；不要求为每个小改动创建一套新计划文档。
- 本地开发与测试使用一次性独立库及合成资料；真实资料/外部 Provider 运行先核验既有授权适用范围和预算，已有明确授权不重复索取。
- 中间产物是敏感运行数据，不放 Git；仓库只收测试用合成输入、脱敏证据索引和复现命令。
- 若模型/服务器/资料条件不齐，完成不依赖它们的节点和测试，并列出精确缺口，不能虚报整链通过。

## 已完成的起点与当前顺序

M1 已选定代表项目并实现选定范围的技术章节、表格、证明附件和缺项原型。当前顺序为 M1.5 核心完整主链 → M2 数据库/Worker/权限底座 → M3 正式上传制作接入 → M4 界面 → M5 三人使用及部署恢复。

产品范围已经确定。实际已执行的测试、真实调用、数据导入及尚未实施的能力以运行记录为准，不沿用最初规划时“尚未实现”的过期状态。

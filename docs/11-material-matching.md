# 资料匹配与来源核对

本轮依据用户 2026-11-15 的近义词匹配检查及实施授权，修正 N3 的有限别名覆盖和关键词直接装配路径。2026-11-16 完成独立语义候选实验后，用户授权将其接入正式 N3 节点，再核对真实原件与更新 Word。没有引入向量服务或新的应用 API。实际验证结果见 [整链记录](09-full-chain-migration.md)。

## 选定原件的正文索引与分阶段说明

`planning.semantic_material_recall.read_selected_originals` 启用 N3 的选定原件索引。先认证复用原目录请求及响应，再读取本次附件明确选定的 PDF 页或 DOCX 图片；新文字不能倒填到旧模型请求中。`material_content_index.py` 的每页/图检查点冻结来源 hash、选页/图片部件、裁剪范围、材料组、读取器版本、输入输出 hash 和读取状态。相同成功单元在同 run 恢复时复用；文件或代码变更仍需子 run。

索引只读取已选范围，不能借整本人工作品的正文为某张证书作证。DOCX 中相同图片部件在多个段落重复引用时，按同一原图资产识别；不擅自采用某个位置的 OCR 或周边正文，重复引用的 OCR 未采用状态保留。原生扫描页标为 `needs_ocr`，暂不支持的裁剪范围标为 `unsupported`，解析失败则保留失败，不能算成功空页。原有 N1 产物保持不变。

`material_content_matching.py` 在逐要求检查点中按新索引重建确定性匹配，并对历史语义候选重新执行来源和条件守卫。历史候选曾被阻断时不能由补读自动解禁；语义候选仍不进入自动装配或资格结论。原目录阶段报告单独保留，新报告记录旧报告 hash、旧词典结果、旧语义状态与新内容匹配状态，分别说明检索依据。

待补清单以要求 ID 和原文短引区分同一汇总项中的各条要求，分别标明词典检索、语义目录补查、原件读取与条件待核。原始 issue、原条件、编号及历史响应来源继续保留；显示层只对登记的系统生成短语做有映射的转换，不修改招标原文。目录未命中、原件未读全、已有候选但条件待核不能混写成公司没有资料。

v62 的原生盘点覆盖 21 组、95 页/图：77 个 PDF 扫描页及 17 张 DOCX 图片需要 OCR；另 1 个已选裁剪页暂不支持原生索引。直接可提取文字为 0，不能宣称证书内容已读完。该轮未购买 OCR 或模型调用；后续本地 OCR 的实现与实际验证如下，人工标书继续作为内容与效果参考。

### 所选证明的离线 OCR

`original_ocr` 是 `planning.semantic_material_recall` 内的可选冻结配置，须同时启用 `read_selected_originals`。当前 Windows 本地适配器使用已安装的 `Windows.Media.Ocr` 和中文语言包，指纹含 OS、OCR DLL、系统 PowerShell、脚本 hash、语言和图像上限。它是当前本机运行环境的可替换适配器，不代表未来 Linux Worker 已支持该引擎；无外部 API 请求或调用费，也不将机器计算资源称为免费。

每个 `material-ocr-*` 单元先按原件、物理页或 DOCX 图片部件重新生成选定图像，核对既有证明图 hash；完整选择 hash、裁剪、旋转和 DPI 进入输入与复用键。OCR 只处理这一图像，不能把整页或父 DOCX 正文当裁剪区域的内容。匹配投影额外认证完整选择 hash，换裁剪/旋转/DPI 不能借用旧识别文字。原生正文反证继续保留，OCR 不得覆盖或削弱它。

真实 OCR 的每次实际尝试独立记录 `ocr.local.*` 事件、span、完整受控输入输出、耗时、引擎版本与校验；不混入 LLM 调用或费用账本。超时有界、无自动重试、无外部回退，失败保留原尝试，恢复仅补未完成单元。只读预检与真正图像识别分别记录；采集关闭或失败时不开始本轮要求完整追溯的识别。

结果保存原始文字、逐词坐标与选区身份，行坐标以选中图像像素为基准。非空文字仅标 `ocr_transcribed_unverified`，空结果为未解决，不能据此认定原图空白。当前本地引擎没有逐词置信度，也不还原可核验的表格关系；内部读取完整性仍未成立，清单单独说明“已机器转录、字段/手写/表格关系待核”。不得从识别文字直接填写事实、判资格或新增装配；OCR 的类别冲突及否定语句作为待核线索，不自动撤除原目录附件。API 费用与本地处理次数分开汇总。

## 当前处理流程

1. 使用本次冻结清单中的材料组、来源、页/图片选择范围及人员/业绩声明，不改变既有分组。`bundle` 与单页附件即使使用相同字符串 ID 也不能混组。
2. 归一常用全称、简称及书写空格，保留原要求。安许证、高企证书、工商营业执照、质量体系证书、高工等仅按受控词表处理；任意新措辞不宣称已经支持。
3. 正文检索限同一冻结原件 hash 下已选择的 PDF 页或 DOCX 图片 OCR 子块。整本人工作品中的其他段落不能冒充某张证书的内容。未读完、不支持读取和未提供解析结果保持可见。直接上传的独立完整图片可按同一来源路径与 hash 绑定；分割页仍必须有明确选页范围，不能借父文档 hash 绕过。
4. 正文或名称中提到某类证明可以形成线索，但说明、申请、缺失声明及其他类别原件不能据此升级为对应证明。原件内容与维护类别冲突时禁止装配。
5. 同一必需类别的多个候选保留歧义；多个不同必需类别分别核对，不能把“营业执照及安许证”当成只能二选一。无候选、有候选但暂不能装配、多个候选待选择分别记录；其中一类缺页或来源未绑定时，即使其他类别已附，也必须保留具体类别及原因的缺项。明确要求某个人的证明时，不能使用另一个人的包。
6. 正常规划与响应章节组织消费同一匹配报告，取消另一路按关键词唯一命中直接装配。完整证明包可以作为带核对提示的候选附件；这不表示证书标准、等级、有效期、派任或项目资格已经成立。

保持 `qualification_result=not_determined`、`project_assignment=not_made`。本阶段不自动判定证书等级高低、历史业绩是否达到本项目全部条件，也不把登记关系或正文命中升级为原件核验。缺项仍能交付样稿。

## 诊断和恢复

- N3 保存一个 `material-index` 检查点及每条待规划要求的 `material-query-*` 检查点。输入绑定要求、材料范围 hash、索引 hash 和匹配版本。后续由固定格式生成的结构投影项单独计数，不混入材料查询分母。
- 同一 run 中成功的查询在失败恢复时复用；发生读取、规则、要求或执行版本变化时依现有合同创建子 run。候选集合变化可能影响多条要求，不宣称跨版本自动复用所有旧匹配。
- 普通事件与 trace 保存 ID、hash、状态、耗时和尝试关联；原要求、候选名、命中页、扩展词、排除依据和条件存于受控检查点/诊断产物。
- 未搜索、表达暂不支持、范围未读完、已搜无候选、相关待核及可装配候选分别表达；这些状态都不能证明公司不存在某项资料。
- 全部查询完成后才完成 N3。单步到 N3 后暂停；成功输入、旧结果和已成功提取窗口保持不可变。

## 语义能力与实验边界

`semantic_materials.py` 提供独立的 `build_probe_executor`，使用现有 Executor、Provider、费用账本和逐查询检查点，不另建模型调用或恢复框架。当前是小目录实验：向模型提供本次冻结的完整材料组目录、维护名称和严格绑定的历史声明，没有先做关键词筛除。超过 80 组或请求长度上限时明确停止，不静默截断后宣称全库已搜；大目录分批/向量检索尚未实现。

确定性入口已有候选时直接保留候选及待核条件，明确免交、其他主体义务或已识别的错人冲突不购买语义调用。其余未命中或歧义表达可请求最多三份候选。模型只返回已有组 ID、目录/条目 hash、逐字引用和简短相关性说明；程序校验严格 schema、引用、文件实际 hash、来源完整性、材料角色、已识别类型及人员约束。引用存在不等于说明正确，任意新表达的人物和条件仍不能宣称已被确定性理解。

模型候选始终保持 `qualification_result=not_determined`、`project_assignment=not_made`、`automatic_assembly_allowed=False`；实验输出不增加事实或装配附件。本次目录的原件图像内容尚未读全，目录名称/历史声明层的召回不能替代 OCR、标准、等级、有效期和原件核验。

实验已增加一项明确条件校验：对可识别的 AMPP CP2/CP3/CP4 代码，仅比较要求与同源人员历史声明。要求 CP4 而声明只列 CP3 时，显示“现有声明不能证明满足所请求的证书条件”，保留原 CP3 和原要求 CP4；不推断等级高低，不断言本人没有另持证书。代码相同也仍待原件和有效期核验。这是已实现的有限条件规则，不代表任意资格条件均已自动验证。明确免交条目不附通用证书待核提示。

嵌套的 `deterministic_report` 保留原词典结果用于比较，显式标记 `comparison_only_not_adopted_for_assembly`，其中的历史候选装配建议不被实验采用。真实调用及离线复验的区别以 run 的输入模式、实际调用事件和费用账本为准；离线报告保留原查询是否使用模型的标记，同时明确本 run 实际新调用为零、历史响应来源及 trace link。

真实实验遵守已有累计 3.50 美元保护，官网直连、逐题一次、无自动校准或重试。语义查询可通过现有执行器单独恢复，但本次付费 runner 使用独占 started 标记，不自动恢复失败请求；新 prompt、模型或来源版本创建新 run。原始 request/response、解析校验、用量及 trace 继续保存于受控产物，普通事件只含元数据。

## N3 主线接入

`planning.semantic_material_recall` 冻结是否启用、逐次最大查询数、可选要求 ID 范围及 Provider 配置。`material_recall.py` 在共享确定性匹配报告之后补找，复用原执行器和独立 `semantic-query-*` 检查点。只有附件响应或资格事实响应进入准入判断；已由原文合同、编制说明或审查动作处理的事项沿用各自来源合同，不因泛化的 `factual_response` 标签购买检索。明确免交、错人、本次签署承诺及已经有业绩候选但尚需核原件的条目不购买补找。原十组业绩不会被模型最多三项的输出截断。

真实运行表明上述模式及来源处理判断仍不能自动排除所有泛化输入：财务/信誉栏目标题、资格材料总引、关键条款转引、未被现有合同处理器覆盖的施工安全承诺及跨响应人关系限制，不能仅凭标题匹配同领域材料。本轮对照完整原文冻结具体查询范围，其余显式延后，不能宣称已实现任意招标文件的自动准入分类。后续应先把栏目/转引关联到具体条款，再补找；不能通过新增一批材料同义词来替代该来源范围问题。

显式查询范围之外的适用条目标为 `deferred_not_searched`；超出配置查询上限直接停止，不静默截断。实际调用失败保持节点失败和成功单元检查点，不用空候选冒充成功。准入、完成、延后、被拦截候选及未读范围在 `n3-material-matching` 和 `n3-planning-report` 中保存。`chain_diagnostics.material_candidates` 是原输入清单的确定性基线，明确 `deterministic_baseline_only`，不能把它当作 N3 语义执行或补组后的完整目录。

语义返回值不进入 `assembly_candidates`。程序只向现有待补事项追加候选名称和核对状态，保留原缺项、编号和条件；没有候选也只能说明冻结目录中未找到，不能证明公司没有材料。新增的完整、来源绑定证明组仍通过共享确定性匹配器决定候选附件落点，其存在不代表资格满足。

`enabled=false` 只关闭模型补找，显式配置的确定性补组仍执行。`additional_evidence` 支持从已冻结 N1 DOCX 补收遗漏的独立证明图。配置只能指定原 source/hash、相邻原生标题块、图片块、包内路径及图 hash；不能传外部路径、自由标题、事实或资格结论。`material_source_selection.py` 再读原 DOCX 精确 XML 位置核对标题及图片，复用原证据转换与检查点，新增来源标为 `provenance_only`。原 N0～N2、原清单和原图保持不变；新目录属于新的 N3 子 run。`plan-assemble` 的 `manifest` 仍是原 N1 输入，派生清单另存 `material_manifest`，不改变正文来源复验要求。此能力不等于已 OCR 或核验整张图的资格条件。

写作复用仅在已有 `exact-writing-inputs-v1` 认证中允许 `planning.semantic_material_recall` 这个明确的非写作配置路径变化；其余配置、原 N1/N2、任务、项目约束、prompt 与实际请求继续严格比较。不能因为配置获准变化就复用输入已改变的正文。

`recorded_source` 是受限于诊断子 run 的离线响应复验：`semantic_replay.py` 从同一运行存储认证原成功 N3 单元、唯一实际调用、原 request/response、账本与 trace，再与当前完整 wire 逐字相等比较。只复验当前选中的要求；不改原候选、无付费回退，旧费用不重复计入新 run，复制受控证据并记录原真实 trace link。输出分别记录新模型查询数和历史响应复用数。检查点保存造成的 JSON 对象键排序不应改变恢复请求：用同一确定性目录重建原顺序，并与检查点整个值严格相等后再使用，不放宽为请求结构近似。

跨 run 复验来源目前要求查询及其直接 `plan-assemble` 父单元属于同一次成功节点尝试；原查询若成功于较早的失败尝试、随后被原 run 续用，当前适配器会明确拒绝，不自动调用模型补买。此限制不改变正常同 run 的持久检查点恢复。

## 验证范围

验证必须覆盖真实 N3 规划入口及附件产物，不仅检查私有函数：全称/简称、无效材料角色、否定与否定后果、与/或、同类候选歧义、缺一种必需证明、错人、错证书类别、选定页范围、来源 hash 变化、独立查询失败恢复和普通日志内容边界。真实资料验证优先使用冻结 N0～N2 与已有字段映射，禁止为验证本地匹配重复购买成功窗口。

## 审核发现与修复

- 原下划线空白格没有填值或待补：已补保守 slot 识别和负例；带单位的复合占位不会整体覆盖固定文本。
- 历史金额和冲突地址误用：已限制项目金额来源；冲突值不进允许事实键集合。
- 表格特殊字体漏读：真实物理页按原件 hash、字体、码点与页码视觉核对，精确转换；不全局删除未知字形。
- 状态文件临时锁导致 N1 中断：保留失败 run，增加有界状态写入重试及每次重试记录；持续失败仍失败。
- 证明候选编号碰撞、ZIP 重名图片、动画图片被截首帧：已修复，增加身份分组、精确部件唯一性及变换前帧数/尺寸负例。
- 模型覆盖配置删除后错误复用旧 N2/N3：校验父/子消费配置依赖与差异；合法起点前的产物才能复用。
- 重试事件将实际调用 span 改成父 unit span：固定实际调用身份，诊断索引独立检查 provider span 和 call attempt，错误关联明确报缺口。
- 公司资料派生来源 hash 被业务字段名误触凭据脱敏：更名业务字段，不放宽脱敏；真实执行器派生来源/产物完整性负例通过。
- 截短“不得自行编写”绕过原格式保护：写作许可回到完整源块与相邻条件，否定/条件/非响应人主体不能授予权限；真实原文 4 处显式许可的离线上下文预检仍可通过。
- 相邻同名人员误合并及字段指向另一张表：仅依据原生姓名合并格或完整重复声明归并；字段、原行、原 grid、表头与单位交叉校验，未知与冲突保留。

## 后续验收顺序

先冻结资料快照的真实处理范围，核对原件读取、格式引用、调用容量及费用，再运行 N2～N6。每个阶段检查受控输入/输出、校验、用量及 trace。失败只补未完成窗口或章节；代码/配置改变创建子 run，允许精确请求 hash 的离线响应重放用于调试，但不能冒充新的真实效果验证。

完整真实标书须核对资格/技术/商务/制作要求及例外，检查实际证明、价格/签章待补、原表和全部渲染页面。资料未解析、证明转换失败或关键格式未读属于处理问题；已知要求而本次资料确实缺少才是业务待补。核心能力和质量尚未完成的部分继续列明，不用一份可下载文件替代验收。

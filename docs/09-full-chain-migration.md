# 核心整链改造与诊断验证

## 当前目标

按用户 2026-11-11 指示，把本产品需要的旧系统核心能力完成独立改造并接通 N0～N6，然后用完整真实样本逐环节查验。复用审视与源码依据沿用 [08](08-legacy-design-reuse.md)，不复制旧运行包、ORM 或迁移链。固定单公司，不引入主体核验或在线改稿。

当前为本地 CLI 整链阶段，PostgreSQL、独立 Worker 服务、账号权限、网页及三人并行尚未实现。正式合同仍以 [架构](04-architecture.md) 和 [日志/恢复](05-observability-and-debugging.md) 为准；本地状态文件与 OS 锁不能代替事务、租约和 fencing。

## 实现与证据

| 环节 | 已接入的能力 | 诊断与边界 |
|---|---|---|
| N0 | 原件/公司快照冻结，PDF 指定页和 DOCX 精确图片部件转换 | 原件、转换参数、派生页均有 hash；逐页 checkpoint；多页证明必须完整，歧义/转换失败阻断 |
| N1 | PDF/DOCX 原生文字、表格网格/合并、页或对象 checkpoint；可配置视觉 OCR 适配器 | 覆盖分母、实际请求与重试进入同一记录；OCR 连接已实现并经离线传输测试，尚未进行真实收费 OCR 验证 |
| N2 | 全文分窗、窄 JSON 候选、精确引文与来源校验 | 每窗口单独持久结果，失败不丢成功窗口；模型声称已检查不等于语义验收 |
| N3 | 指定格式原段落/原表顺序、事实键映射、证明匹配、技术写作单元 | 固定表格由代码填值；未知公司事实/报价/签章显式待补；关键格式未决先存报告再失败 |
| N4 | 既有逐技术单元写作与受限参考改编，装配固定文字/表格/证明 | 模型不直接产生公司事实；每次实际 HTTP 尝试、校验失败、未知用量均独立记录 |
| N5 | 结构与引用核对、缺项/响应类别 | 程序事项可标无需正文；不能把待补或模型覆盖声明计成已实质响应 |
| N6 | Word/待补清单、不可变文件、最终单步完成 | 采用冻结参考样式和原表结构；消费 N0 转换好的证明页，不声称任意原模板无损继承 |

公司资料另有 `LIBRARY` 准备任务，使用相同执行器。已接原生基本情况表的事实候选、单元格定位、重复值合并、冲突拒用、用户授权派生资料标识及不可变快照。表中其他格含图片时，只允许采用与未读对象及合并范围不相交的已读字段；原表和源文件仍标部分读取。人员声明和历史项目按显式表域准备，独立保存，不混入本次报价或自动认定为本次拟派人员。原 grid、合并、表头、单位和每个单元/行引用相互校验；同名不能直接合并。N3 可列出声明候选及未决状态，尚不自动证明资格、有效期或当前可用性，不能称全库导入。

所有节点使用同一个执行器。已成功节点重做或冻结版本变化创建子 run；仅继续同版本失败/暂停任务时复用成功单元。采集关闭、写入失败、不完整 trace 需显示；密钥不得进入任何产物。`diagnose` 提供只读诊断索引，关联节点/单元/实际调用的 trace、输入输出、校验和复用来源，检查证据缺口。

合成整链验证包含实际 DOCX 原表读取、LLM 事实键映射的离线传输 stub、写作、证明图片、缺项、程序事项不入正文、跨执行器实例继续以及只重做 N6 时零新增调用。这里的 stub 不计真实模型或效果验证。

## 运行方式

PowerShell 在项目根设置 `$env:PYTHONPATH='src'`，用项目 Python 执行 `-m company_bid.cli`。自动流程配置 `pipeline: automatic`，输入符合 `IntakeManifest`；敏感原文/配置放受控目录。密钥仅用已有环境变量或 `--credential-file`，不要写入 JSON 配置。

```text
python -m company_bid.cli --root .local/runtime --config <config.json> create --input <manifest.json> --stop-after N1
python -m company_bid.cli --root .local/runtime --config <config.json> step <run> --stop-after N2
python -m company_bid.cli --root .local/runtime --config <config.json> resume <run>
python -m company_bid.cli --root .local/runtime --config <config.json> rerun <run> --from-node N3
python -m company_bid.cli --root .local/runtime diagnose <run>
python -m company_bid.cli --root .local/runtime diff <old-run> <new-run>
```

诊断索引和 diff 写入受控文件，终端只输出位置与有限元数据。`diagnose` 可在实现版本已变化后只读检查旧 run，不需要执行旧节点代码。`recorded_candidates` 必须匹配完整请求 hash，明确是离线候选，不计作实际模型调用。

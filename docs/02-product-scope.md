# 产品与交付边界

## 日常使用

管理员一次性维护公司名称和常用基础字段，上传资质证书、人员、业绩、制度、产品及可授权使用的参考方案。资料保留原件、版本、有效期和来源；OCR/模型提取只是候选，关键公司字段在资料维护时核对，不在每次制作中反复确认。

使用者创建项目、上传招标文件，可选补充报价表、项目人员或指定资料，然后点击“开始制作”。系统自动执行所有节点；页面显示当前阶段、已完成范围、警告和耗时。用户可以关闭页面，任务继续执行。

结束后下载 `投标文件.docx` 与 `待补清单.docx`。需要引用的公司证明附件实际进入文档或明确列为独立附件；不能只输出文件 ID。原始附件可另打包下载，但压缩包不是替代 Word 的主交付。

目录错误、措辞修改、报价补齐和签字盖章在线下处理。重新制作生成新版本，不接收用户线下 Word 回传合并；首版避免双向同步。

## 缺项与失败的区别

| 情况 | 处理 | 页面与文件表现 |
|---|---|---|
| 缺证照、人员、业绩证明或报价 | 对该项插入显眼待补标记，继续其余内容 | “生成完成，需线下补充”，清单列章、字段、来源要求、补充动作 |
| 技术方案尚无历史范文 | 从本项目要求生成拟实施方案 | 不冒称已有项目经验、确定人员设备或已取得证照 |
| 材料过期、主体不符、相互冲突 | 不作为有效事实采用；保留原因 | 指定缺项，不能用相似材料代替资格证明 |
| 部分章节生成失败但已知要求清楚 | 有界重试后该章标待补，保留已有章节 | 显示具体失败章节，不显示全部内容已生成 |
| 核心招标文件损坏、关键页未读出、关键要求窗口遗漏 | 停在失败节点，允许补文件或重试 | 不把未知要求变成“无要求”，不发布貌似完整的投标 Word |
| 整体公司主体不明或关键输入冲突 | 暂停生成并指出输入问题 | 不能自动选任意公司或猜测主体 |
| 文件装配损坏、权限错误、取消 | 不发布本次结果 | 保留可诊断原因，已有其他版本可继续下载 |

每个待补标记使用稳定编号，如 `【待补 M-012：项目负责人资格证明】`。清单与正文双向对应。出现待补项时不使用“可直接投标”或“全部符合”等字样。即使没有自动检出的缺项，也只表示系统检查完成，提交前仍由使用者线下审阅。

## 公司事实与方案写作

- 事实：公司名称、资质、有效期、人员、业绩、设备、价格等，必须来自本次冻结的资料或明确人工输入。
- 方案：技术路线、组织方法、质量控制、实施步骤、风险措施，可以针对招标要求编写；表述为拟实施安排，不据此制造既有事实或无依据的额外商业承诺。
- 金额、报价明细、签章、授权人和未知承诺值不由模型填补。用户输入的报价可以按明确公式校核，不替用户定价。
- 历史人工标书仅能作风格、结构和方案参考，不能自动升级为公司事实或标准答案。
- 文档中的“忽略系统要求”等文字作为源文处理，不成为模型工具或流程控制指令。

## 自动目录与格式

优先使用招标文件规定的目录、章节、表格及附件顺序；未规定部分使用一套公司默认模板。目录只在内部校验和冻结，使用“自动校验”语义，不写成人工确认。

固定格式优先保留原字段、表格形态、顺序和措辞。PDF 表格转成可编辑表格须核对合并单元格与标签；无法可靠重建时明确标记待人工套用，并提供原页参考，不能把图片表格称为完全可编辑。证照、签章扫描件以可读图片附件呈现是允许的，主正文与普通表格必须可编辑。

目录采用 Word 标题样式和可更新目录字段，不能用估算页码冒充排版页码。在目标 Word/WPS 环境验证目录更新、页眉页脚、表格跨页和图片尺寸。导出前能自动更新字段则在受控渲染进程完成，否则在交付说明中明确一次更新操作，不伪造目录数字。

## 最小界面

| 界面 | 必要操作 |
|---|---|
| 公司资料 | 档案维护、上传分类、有效期、来源和可用状态 |
| 项目列表与新建 | 上传、开始制作、查看历史版本 |
| 项目结果 | 阶段进度、警告、取消、失败续跑、下载 Word/清单/附件 |
| 调试详情 | 节点时间线、trace、输入输出、尝试差异、单步与从指定节点重跑 |

仅设管理员和成员两种角色。首版固定公司内的项目按团队共享，用户身份仍须可追溯；公司资料配置、敏感调用原文和调试配置由管理员控制。普通成员可查看任务状态和下载团队项目结果。

## 输入范围与首版边界

首版处理 PDF 与 DOCX 招标文件、常见 PDF/图片/DOCX 公司资料；XLSX 仅作为项目补充报价/清单，经专门解析。压缩包、宏文档、加密文件、旧 DOC 及其他格式明确提示转换，不能接收后假装完整解析。文件大小、页数和超时上限在首批样本测量后配置并在上传处告知。

首版不做多公司、在线 Word、目录编辑器、聊天改稿、自动投标提交、复杂审批、多租户计费、通用浏览器或多 Agent 工具运行。诊断单步是调试能力，不变成所有用户制作时必须点击的流程。

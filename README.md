# 公司内部标书制作系统

规划日期：2026-11-10。独立项目目录：`F:/company-bid`。M1 已提供选定范围的真实 Word 原型；按用户后续指示，当前进入核心能力整体改造与 N0～N6 整链验证。先接完整读取/要求/原格式/事实匹配/正文/附件主链并逐节点检查，再完善平台。当前进度见 [整链改造与诊断验证](docs/09-full-chain-migration.md)，历史原型见 [M1 记录](docs/07-m1-prototype.md)。

目标是让固定一家公司的 2～3 名同事同时使用：提前维护公司资料，每次上传招标文件及可选补充资料，系统自动读取、整理要求、生成目录、编写正文、装配附件，最后下载可编辑 Word 和待补清单。目录与正文在线下修改。

2026-11-12 已迁移至 F 盘。后续开发和新运行以 `F:/company-bid` 为根；`E:/company-bid` 仅保留指向新目录的目录联接，以兼容已有冻结路径和 Python 启动器。原有代码、未提交修改、资料、日志及检查点均已保留，E 盘原副本已移除。迁移校验记录位于 `.local/evidence/storage-migration-20261112/`。

## 已确认的产品决定

- 固定一家公司的 2～3 人使用，不做公司主体选择、比对或核验。成员仅查看和操作本人的项目、标书及生成记录；超管可查看全部。
- 公司公共资料库共用，由超管维护；每个人上传的项目补充资料随项目隔离，不自动成为公共资料。
- 公司资料提前上传，包括资质、人员、业绩等；每次制作冻结所用资料版本。
- 中间目录自动生成和校验，不设置在线编辑、逐章审批或目录确认步骤。
- 缺公司证明、报价或其他人工信息时，仍交付明确标注缺项的 Word 和待补清单。
- 公司事实不能编造。技术方案可以依据招标要求起草拟实施方法，与已具备的能力和历史业绩明确区分。
- 每次生成对应独立版本；下载内容不因后来重跑而改变。
- 日志、trace、节点输入输出、每次外部调用和重试均可追溯。
- 支持失败断点续跑、单节点执行和退回任意前置节点重跑，保留调试前后结果。

## 核心流程

```mermaid
flowchart LR
  A[上传招标文件] --> B[解析与必要的 OCR]
  B --> C[提取要求和格式规则]
  C --> D[匹配公司资料并自动编排目录]
  D --> E[编写章节与填表]
  E --> F[核对内容并装配附件]
  F --> G[生成 Word 和待补清单]
  G --> H[下载后线下修改]
  M[预维护公司资料] --> D
```

调试与正式运行使用同一套节点和执行器。调试分支只改变执行范围和冻结配置，不引入第二条生成链路。

## 从本地核对写标前的项目信息

自动链的 `company-bid --root <受控运行目录> --config <配置> create --input <清单> --review-before-writing` 会先读招标并匹配材料。如果需要本次安排负责人、核对社保或选择签署身份，会在写正文前返回一份可读简表和一份可复制填写的 JSON。省略该选项可照常自动制作。使用同一个运行目录继续操作。

- `company-bid --root <受控运行目录> project-questions <run_id>` 从已成功的 N3 生成当前项目的简表和 JSON，仅在受控目录保存。
- 复制 JSON，在副本中填 `reviewed_by` 和本次能够确定的 `answers`。可用键和选项由 `questions` 给出。人员、用工主体、代理人姓名使用字符串，签署身份取 `legal_representative` 或 `agent`。截止时点包含 `submitted_before`（北京时间 ISO 8601）和 `source_ref`（冻结招标来源）。缴费记录包含 `person_name`、`employer`、`paid_on`（年-月-日）与 `source_ref`。已存在的来源需对应本项，传入新凭证时使用 `supplied_payment_proof` 并在下一条命令加 `--payment-proof <PNG或JPEG>`。可留出暂未确定的项目。
- `company-bid --root <受控运行目录> apply-project-answers <run_id> --input <填写后的副本>` 从冻结计划创建子版本并生成 Word。也可加 `--queue-only` 暂存子版本。本阶段补录后写作仅接通离线预备正文或已认证的完整回放。新增或变更正式招标要求的公告、澄清需作为招标输入重新读取。
- 本次跳过全部补录时，使用 `company-bid --root <受控运行目录> resume <run_id>`。补录前后均保留公司缺项和办理事项，真实签字、盖章在线下办理。

## 实施起点

先做一个包含真实技术章节、表格、证明附件和明确缺项的纵向原型，证明内容能用、Word 能改，并从第一步具备节点记录和恢复能力。通过后再扩展样本、界面和并发。

本目录不依赖旧项目的运行路径、数据库或工作区；旧实现仅作设计与测试参考。用户授权的文件已进入 M1 本地受控资料目录；PostgreSQL 入库、API/Worker 服务、界面、部署和并发验证尚未实施。旧项目的接受结论不等于新系统已通过验收。
